# Guided Goal Discovery｜目标引导模式

[English](README.en.md)

**当前版本：v0.3.1｜GPT-6 Astra 多轮协作适配**

一个通过“一次一个关键问题”，把模糊意图、零散想法和相互冲突的偏好，逐步整理为目标共识与 0→1 启动方案的 Codex Skill。

它不会要求用户先写好完整 brief，也不会过早给出一套看似完整的解决方案。Skill 会先帮助用户明确项目为何存在、面向谁、应产生什么变化，再确定本阶段的交付物、边界、判断标准和真正可开始执行的第一步。

每轮默认提供两到三个编号文字选项，等待用户选择或补充，再根据回答继续下一轮。用户始终可以混合多个方向、提出其他想法或推翻之前的选择。点击控件只是可选的呈现方式，不是使用前提；模型自认为理解充分，也不能代替用户完成确认。

**输入**：模糊意图、稀疏创意种子、相互冲突的偏好、不知道从哪里开始的项目，或会因不同理解产生完全不同结果的需求。

**输出**：经过确认的目标共识、项目形态、判断标准、0→1 启动方案，以及面向执行流程的无损交接。

## 功能

- 将“不知道”“没有想法”和难以表述视为有效起点，而不是要求用户先完成专业需求文档。
- 每轮只提出一个最能改变方向的问题，避免多问题问卷和低价值追问。
- 主动提出两到三个真正不同的工作假设，帮助用户通过吸引、抗拒和修正发现目标。
- 明确区分目标、交付物和实现手段，避免把用户最先想到的形式误当成真正目的。
- 通过“意义、形态、判断”三个阶段推进，仅在关键理解尚未确认时暂停确认。
- 使用目的、对象与情境、体验、交付物、范围、边界、成功证据和取舍八个内部维度。
- 默认输出编号文字选项并等待回答；可点击控件仅为可选增强。
- 保留自由输入和撤回权；探索选择视为暂定信号，明确的确认或开始指令直接生效。
- 最终生成“目标共识＋0→1 启动方案”，并将全部边界和优先级交接给执行流程。
- 不打断清晰请求、事实问题、诊断、修订或方向已经对齐的连续工作。

## 方法原则

| 原则 | 实现方式 |
|---|---|
| 一次一问 | 每轮只提出一个会实质改变方向的问题，不采用固定问卷 |
| 意义优先 | 先明确项目为何存在、面向谁以及应产生什么体验，再讨论媒介、格式和工具 |
| 主动假设 | 用户无法回答时，提出两到三个含义真正不同的工作假设，而不是把创作负担退回给用户 |
| 选项与等待 | 默认输出两到三个编号选项及自由补充入口，等用户回答后再进入下一轮 |
| 自由修正 | 始终允许选择“其他”、混合方向、补充条件、撤回选择或替换整套问题框架 |
| 三层分离 | 持续区分目标、当前交付物和实现手段，不把形式直接等同于目的 |
| 三阶段推进 | 按“意义 → 形态 → 判断”持续协作，阶段理解由用户确认，不把模型推断当成已确认 |
| 八维判断 | 内部检查目的、对象与情境、体验、交付物、范围、边界、成功证据和取舍 |
| 状态透明 | 将信息区分为已确认、暂定理解、已排除和待确认，不把推断伪装成事实 |
| 可识别成功 | 在启动前明确不可妥协项、排除方向、优先级冲突和可观察的成功证据 |
| 无损交接 | 输出完整的目标共识与 0→1 启动方案，让执行流程无需要求用户重新描述需求 |

## 选项与多轮协作

v0.3.1 默认采用“文字选项 → 用户回答 → 更新理解 → 下一轮”的流程：

- 每轮一个关键问题，给出两到三个具体方向及简短说明；
- 明确允许回复序号、混合方向或自由补充，然后停下等待回答；
- 用户选择后继续梳理尚未明确的问题，不立即生成完整结果；
- 阶段确认只确认该阶段，“这一项你来选”也不等于授权模型替代整个协作过程；
- 共识确认后形成启动方案，经用户要求开始才交接执行；明确要求停止提问、直接代选并执行时，尊重这一改令。

仓库不捆绑自定义 GUI。若宿主有合适的控件，也可用它呈现同样的选项；控件回执和默认预选不算用户回答。

## GPT-6 Astra 支持

v0.3.1 参考 [OpenAI 的 Astra Skill 迁移建议](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra)，明确 Skill 触发条件，并强调用户要求的多轮协作，而非让模型自行推断完整目标后直接交付。Skill 不绑定模型，也不会修改全局模型设置；请在宿主中选择 **GPT-6 Astra**，然后调用此 Skill。其他兼容 Skill 的模型仍可使用。

| 适配点 | 实现方式 |
|---|---|
| 正确触发 | 用户调用 Skill 或要求引导提问时，进入协作流程；不自动打断普通明确任务 |
| 每轮有选项 | 提出一个关键问题及两到三个具体方向，并允许自由表达；不依赖点击交互 |
| 等待真实回答 | 提问后停下，根据用户回答再继续；不模拟回答或默认替用户选择 |
| 不抢先交付 | 不因模型自信、局部选择或阶段确认而直接跳到最终方案 |
| 保留多轮协作 | 梳理意义、形态和判断，逐步确认；允许改口，不设机械的固定轮数 |
| 明确交接 | 共识确认后形成启动方案，经用户要求开始才进入执行；明确停止提问的指令优先 |

本次重点是调用与协作行为的指令适配，不强求 Astra 的点击交互。结构校验不等于模型行为测试，多轮协作的实机验收项目见[验收清单](tests/acceptance.md)。

## 安装

将 `skills/guided-goal-discovery` 复制到 Codex skills 目录。

### PowerShell

```powershell
$skillsRoot = Join-Path $env:USERPROFILE ".codex\skills"
Copy-Item -Recurse -Force .\skills\guided-goal-discovery $skillsRoot
```

### macOS 或 Linux

```bash
cp -R skills/guided-goal-discovery ~/.codex/skills/
```

如果 Skill 没有立即出现，请重启或刷新 Codex。

## 使用

明确调用 Skill：

```text
使用 $guided-goal-discovery，每轮问我一个问题并提供选项，等待我选择或补充后再继续，通过多轮协作确认目标，不要直接给出最终方案。
```

用于模糊创意：

```text
使用 $guided-goal-discovery 帮我找到这个影像想法真正想表达的内核，再决定最适合的表现形式。
```

用于尚未定义的项目：

```text
使用 $guided-goal-discovery 帮我把这个零散想法整理成目标共识和可以正式开始的 0→1 方案。
```

## 核心交付

最终输出包含四部分：

1. **意义共识**：核心目标、重要性、对象与情境、预期体验或变化。
2. **项目形态**：当前交付物、范围，以及本阶段明确不做的内容。
3. **判断标准**：不可妥协项、排除方向、取舍优先级和成功证据。
4. **0→1 启动方案**：首个里程碑、所需输入与资源、推荐执行路径和交接对象。
